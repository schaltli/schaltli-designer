# Card clip

Spec for module `card-clip` of docs/2026-11-03-cards.md, drafted
2026-11-03. **Status: approved by the user on 2026-11-03.**

## Objective

A label with a fill of its own docked at the top of a round card stands out
past the card's corners (the user, 2026-11-03, with a screenshot). Nothing
can cut it: a free area is dissolved on export, so a device never knows an
object came from it, and the colour boards' canvas clips to rectangles only.

After this module a free area can **clip** what it holds to its own shape,
round corners included, on every device and in the designer alike: a
heading with a fill takes the card's corners.

Success looks like: the card of the screenshot - a round card, a label with
a fill docked at its top - shows the label's corners rounded like the
card's, inside its edge, identically in the designer's preview and on the
knob, the 4", the 4.3B, the PaperS3 and the Android app (HIL at 0 px where
the suites compare at 0 px).

**Decisions** (the user, 2026-11-03):

- **A Clip toggle** on every free area; **on by default for a card** (a
  free area with a Look), off for a plain one.
- **Clipped inside the edge**: what the area holds ends where its edge
  begins; the edge always shows, over a coloured heading too.
- **A device whose firmware cannot clip refuses the project** (Deploy is
  blocked, or offers the firmware update that can - as for any feature).
- **All devices together**: colour boards, PaperS3, Android app and the
  designer, in one module and one release.

## The shape

The clip is exactly the set of pixels the area's box fills inside its edge:
`fillRoundRect(x + edge, y + edge, w - 2·edge, h - 2·edge, max(0, radius -
edge))` as Adafruit GFX draws it - the integer midpoint circle the box is
drawn with on every device and that `components/canvas/renderers/
render-box.ts` already mirrors to the pixel. A pixel of a clipped object is
drawn only where that shape has one. No anti-aliasing: the box has none, so
a clipped heading meets the card's corner pixel for pixel.

An area inside a clipping area clips by both: a pixel shows where every
shape around it has one.

## Behaviour

- **Clip**, a toggle in the free area's «Free» section, shown for every free
  area. A card starts with it on; a plain free area off. Set by hand, it
  stays as set when the Look changes.
- **What is clipped:** every object the area holds, at any depth - docked,
  anchored, in a table inside it, a switcher's panels. The area's own box
  is not clipped.
- **In the designer:** the editor and the preview draw clipped objects
  clipped; selection outlines and handles are not clipped.
- **On export** each object the area holds gets `properties.clip`, the list
  of shapes it is clipped by, outermost first, each in the same space as the
  object's own x and y: `{ x, y, width, height, radius }` - already inside
  the edge.
- **Devices:** the DDF declares the feature `clip` in `supportedFeatures`.
  A project using a clipping area deployed to a device without it is
  blocked, or offered the firmware update whose release declares it
  (`lib/deploy-plan.ts`, as `local-topics` or `charts`).
- **Firmware** (colour boards and PaperS3, `ColorScreenRenderer`): an
  object with `clip` is drawn with that clip set on the canvas - every
  pixel write, span and fill tested against it - in full redraws and in
  partial ones (a live value, a drag) alike.
- **Android app:** the same shape, by the same integer algorithm, as a
  per-row span mask applied while the object draws.

## Not in scope

- Anti-aliased clipping.
- Clipping on a screen, a switcher's panel or a table (only free areas).
- Shapes other than the rounded rectangle.

## Device contract

New in §2.1 (object properties, every type): `clip`, an array of
`{ x, y, width, height, radius }`, outermost first, in the object's own
coordinate space. A device that declares `clip` in `supportedFeatures`
draws no pixel of the object outside any of them, by the rule of §«The
shape» above, written out with its integer arithmetic. A device without the
feature never receives `clip`.

## Code

- Designer
  - `lib/clip.ts` (new): the shapes an object is clipped by; the row spans
    of a shape (the GFX midpoint circle, shared with render-box.ts).
  - `lib/object-groups.ts`: export writes `clip` while dissolving a free
    area with Clip on.
  - `components/property-panel/free-properties.tsx`: Clip.
  - `lib/card.ts`: a card's Clip on by default.
  - `components/canvas/canvas.tsx`, `lib/render-screen.ts`: draw clipped.
  - `lib/deploy-plan.ts` / its callers: the `clip` feature.
  - `docs/device-contract.md`: the property and the rule.
- Firmware (`schaltli-firmware`)
  - `src/ClippedCanvas16.h`: a shape clip beside the rectangle one.
  - `src/project/ProjectLoader.cpp`: `clip` read into `ScreenObject`.
  - `src/project/ColorScreenRenderer.cpp`: the clip set around each object.
  - The DDFs of the knob, the 4", the 4.3B and the PaperS3 declare `clip`.
  - The shape drawn once by Adafruit GFX itself into a one-bit canvas and
    read back as row spans (built so instead of a third port of the circle:
    the board's mask is its own box's pixels by definition; whether the
    designer meets them is the HIL specimen's at 0 px). No native test -
    the native environment has no Adafruit GFX.
- Android (`schaltli-android`): the project model reads `clip`; the screen
  renderer masks each object by it; its DDF declares `clip`.

## Testing

- `e2e/card-clip.spec.ts` (new): the spans of a shape for fixed radii and
  edges, against a fixture shared with the firmware's and Android's tests
  (`lib/fixtures/clip-spans.json`); export writes `clip` for every depth and
  nested areas; Clip on by default for a card; a project with clipping is
  blocked for a device without the feature.
- `e2e/card-clip-canvas.spec.ts` (new): the toggle; the screenshot's card
  drawn with the label's corners clipped, pixel-checked in the preview.
- `hil/conformance/specimens.js`: a specimen of a round card with a filled
  heading docked at the top and a nested clipped area, compared at 0 px on
  the knob, the 4", the 4.3B and the PaperS3, and on Android in its suite.
- Android unit test `ClipSpansTest`: its `roundRectSpans` against
  `clip-spans.json` (copied into its test resources).
- The Android HIL fixture (`hil/android/fixtures/build-android-test.js`):
  a screen «Karte» with the same two clipping cards, last.

## Boundaries

- **Always:** pixel-identical shape on every device and in the designer;
  `test:quick` per change; handbook in the same work.
- **Ask first:** the firmware release itself (as always); anti-aliasing.
- **Never:** `clip` sent to a device that does not declare it.
